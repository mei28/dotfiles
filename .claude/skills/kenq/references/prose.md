# 文と段落

本文を書くとき、推敲するとき、日本語原稿を英語にするときに読む。

一般の文章規範はここに書かない。
日本語原稿は `../../japanese-tech-writing/SKILL.md`、英語原稿は `../../tech-writing/SKILL.md` を併用する。
このファイルは論文に固有の差分だけを持つ。
推敲を終えた原稿をファイルに書き出したら `../../japanese-tech-writing/scripts/lint.sh <file>` を実行し、指摘ごとの採否を台帳に記録する。`.tex` はそのまま渡せる。手順は `../../japanese-tech-writing/references/lint.md`。

## 既知から未知へ

文の前方に読み手が既知の事実を、後方に未知の事実を置く。
次の文では、前の文で未知だったものが既知になり、それが文頭に来る。

```
一文目  A（既知） → B（未知）
二文目  B（既知） → C（未知）
三文目  C（既知） → D（未知）
```

規則は二つある。

1. 一つの文で使う主人公は 2 つまで。主人公同士の関連を明確にする
2. 読み手にとってその主人公が既知か未知かをよく考える。何ページも前に登場した主人公は、読み手が覚えていない

良い例。

> エチオピアではテフと呼ばれる穀物を加工した食品が主食となっている。
> まず、テフを粉末状に加工する。この工程をオフチョベットと呼ぶ。
> 次に、オフチョベットしたテフを水と混ぜ合わせる。この工程をマブガッドと呼ぶ。
> 最後に、マブガッドしたものを発酵させると、生地の元となるリットができあがる。

悪い例。同じ内容だが順序を逆にしたもの。

> マブガッドはオフチョベットしたテフを水と混ぜ合わせることである。
> また、オフチョベットとはテフを粉末にすることである。
> テフはエチオピアの穀物であり、その加工食品が主食となっている。
> マブガッドしたものを発酵させると、生地の元となるリットができあがる。

規則を守らないと認知負荷が上がる。
それだけでなく、情報の欠落や文章の破綻に、書き手自身が気づきにくくなる。

骨組みをこの順序で組んでから AI に修正させる。
順序が崩れた文章を渡しても、AI は綺麗に直せない。

## 用語

- 最初に使うときに定義を説明する
- 略語は必ず何の略であるかを記載する。使う前に定義する。査読者が締切 3 日前に 15 本を渡された非母語話者の 1 年目の学生である可能性を考える
- 同じ概念を複数の呼び方で参照しない。表記が揺れると、読者は同じことを言っているのか判断できなくなる
- 研究室内で符牒のように使っている言葉や言い回しを使わない
- その分野で一般的に使われている意味と、自己流の意味がずれていないか確かめる。読者は一般的な意味で読み進み、途中で著者独自の定義だと気づく
- 具体的に書く。SAX は統計的アルゴリズムではなくデータ表現である。DTW は metric ではなく measure である

## 曖昧な語と常套句

正しいが曖昧な用語を使わない。HCI では「人にやさしい」「直感的な」がこれにあたる。
何をもってそうだと言えるかを正確に定義することが難しく、情報量がない。

「革新的な」「次世代の」も同じである。
これらは証明が困難であり、売りがないことを示してしまう。

「直感的なインタフェースを作る」ではなく、直感的になるための具体的な仕掛けを述べる。

## 口語表現と外来語

- 口語的表現を避ける
- 技術用語として定着した外来語はよい。「シーン認識」の「シーン」は問題ない
- 定着していない外来語で、日本語で説明できるものは口語表現を疑う。「様々なシーンで使われている」は「様々な場面で使われている」とする。「シンプルな解決方法」も同様

## 弱い言葉を避ける

| 弱い | 強い |
|---|---|
| 動的な系列では正確な結果を出せないかもしれない | 動的な系列では不正確な結果を出すことが [7] で示されている |
| 本論文では近似と索引付けを試みる | 本論文では近似と索引付けを行う／本論文では初めて近似と索引付けの方法を示す |
| 本研究は同一場面の映像の検出と検索を目指している | 本研究では同一場面の映像を検出し検索する新しいアルゴリズムを導入する |
| DTW はコストを最小化する経路を見つけようとする | DTW はコストを最小化する経路を見つける |
| 分散環境での実時間集約クエリ監視は大きな課題であるように見える | 分散環境での実時間集約クエリ監視は大きな課題として知られている [1,2] |

日本語で書く段階でも同じである。
「〜を行う」「〜することが可能である」は「〜する」「〜できる」にする。
本文内の根拠で確定していることは言い切る。不確実性を表すための弱い述語は残す。

## 言い過ぎを避ける

弱すぎるのと同じくらい、強すぎるのも問題になる。

- 「我々のアルゴリズムは決定木より良いことを示した」
- 実際に示したのが「データが相関しているとき決定木より良くなりうる」なら、そう書く
- あるいは「Iris と Stock のデータセットでは我々のほうが高精度だった。どのような条件で成り立つかは今後の課題である」と書く

## 語の正確さ

英語原稿で特に問題になるもの。

- optimal は「とても良い」ではない。証明できないなら「最も良い結果を出した値を選んだ」と書く
- proved は「示した」ではない。実験はめったに証明にならない。「実験によって証拠を示す」と書く
- significant は統計的主張と日常語が混ざる。統計的有意なら、有意水準まで書く
- complexity は計算量と「込み入っている」が混ざる。計算量なら O 記法で書く
- it is easy to see は常套句である。そのうえ、本当に易しいか疑わしい
- actual と theoretically は、たいてい文中で意味を持たない
- etc は、残りの項目が自明なときだけ使う。「安定性や拡張性などの性能要因」は使えない
- correlated を「関係がある」の意味で使わない
- 「本論文では」は、読んでいるのがこの論文なので、ほとんどの場合不要である

## 能動態と指示語

自分の業績は能動態で書く。受動態は他人の業績や一般に知られた事実に使う。

| 受動 | 能動 |
|---|---|
| It can be seen that | We can see that |
| Experiments were conducted | We conducted experiments |
| The data was collected by us | We collected the data |

it、this、these、that の出現をすべて確かめ、指すものが一意に決まるか点検する。

> We used DFT. It has circular convolution property but not the unique eigenvectors property. This allows us to...

この This は、DFT を使ったことか、畳み込みの性質か、固有ベクトルの性質か、決まらない。

## 日本語の文法で崩れやすいところ

- 順接の「が」を使わない。逆接の「が」はよい。「晴れでしたが、明日も晴れ」は文を切る
- 「の」を重ねない。「父の写真」は三通りに読める。「父を写した写真」のように言い換える
- 「こと」「もの」は意味が広い。具体的な語に置き換える
- 「AもBも」の A を省略しない。「新幹線で行く方法もある」は「飛行機でも新幹線でも行ける」とする
- 表記を統一する。「時」か「とき」か、「コンピュータ」か「コンピューター」かを決める
- 脚注は極力避ける。視点の移動が読みにくさを生む。例外の記述は本文に収める工夫をする
- 肯定文を先に置き、否定文は補足に使う

## 英語にする段階

論理とパラグラフ構成は日本語の段階で確定させる。英語化では直らない。
ネイティブチェックでも表面的な誤りは直るが、論理とパラグラフ構成は改善しない。

英語化で新たに点検するのは、この節の「弱い言葉」「語の正確さ」「能動態と指示語」だけである。
段落の順序や論の筋を英語化の段階で直したくなったら、日本語原稿に戻って直す。

スペルミスは真摯さの欠如と判定される。参照表記の食い違いも同じである。

## 削る

すべてを書かない。本当に伝えたいことを選ぶ。
書きたいことを押さえて、それでも溢れてくる部分だけを書く。

優先度をつける方法として、箇条書きにして点数を付け、線を引いた以上の項目だけを書く。

時間をおいてから読み直す。書いた直後は自分の思い込みに支配されている。
