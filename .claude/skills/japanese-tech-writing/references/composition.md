# 構成と段落の役割

文書の構成を決めるとき（読者の設定、導入とまとめの分担、例の選び方、説明の順序と分量）に読む。
段落と論証の原則は `../SKILL.md` の「段落と論証の構成」にある。
この規範の由来は `upstream-humanizer.md` にある。

## 読者と到達点

書き始める前に、文書ごとに想定する読者を決め、その読者について次のことを整理する。

- 読者がもともと持っている知識
- 本文で説明しなければならない前提
- 読み終えた読者が新たにできるようになること（何を説明でき、何を判断でき、何を実行できるか）

統計の知識がある読者でも、法律の知識があるとは限らない。
題材を決めただけでは到達点は決まらない。
読者がどの関係をつかめばよく、どんな判断を下せるようになればよいのかまで具体的にする。
依頼が概要であれば、扱う範囲の全体を見渡せるように書く。
どんな読者を想定したかを本文で宣言しなくてよい。

概要や規模感を伝える文書なら、結論とその主な理由が読み取れるところまで書く。
計算の再現、実装、設計のどこまでを扱うかは、文書の目的に照らして決める。
説明を一つ足すか省くかを決めるときも、基準はこの到達点に置く。

中心の問いとその答え、主な理由、結論を左右する前提は、本文を読むだけでわかるようにする。
説明を足すときは、その説明を理解するのに要る用語・前提・計算まで勘定に入れて、読む負担を見積もる。
気軽に読まれる文書では、扱う概念を主題に要るものだけにする。

## 導入・各節・まとめの分担

文書の部分ごとに、担う内容を次のように分ける。

| 部分 | 担う内容 |
|---|---|
| タイトルと概要 | 本文がどの問いに答え、どこまでを扱うのか |
| 導入 | 問いをつかむのに要る背景と、主な答え |
| 各節 | 答えの理由。到達点に見合う仕組みや具体例で説明する |
| まとめ | 読者が得た理解と、それを実際の利用や判断へどうつなげられるか |

ある情報をその位置に残すときは、文書全体との関係と、その節や段落の問いに答えるうえで何の役に立つかの両方を確かめる。
対象の特徴を説明している途中に、調査や計算をどう扱ったかの話が挟まることがある。
その話がその位置にあることで、読者の理解や判断の何が進むのかを確かめる。
別の問いに答える情報は、その情報を使う節か補足へ移す。
文書の目的に要らない情報なら省く。

各位置での詳しさは、読者がそこまでに何を理解したかに合わせる。
導入に置く説明は、問いと主な答えを伝えるのに要る最小限にとどめる。
比較の項目・費目・工程・条件の細かい内訳を冒頭に並べない。
内訳はそれを使って理由を説明する箇所で出す。
省いても、上位の概念でくくっても要点が伝わるなら、短い言い方を選ぶ。
共通の前提についても、冒頭に置くのは冒頭を理解するのに要るものだけにする。

文書全体の導入と、個々の説明や比較の前提を示す段落とは、役割の違うものとして分けて考える。
いくつもの項目に共通する用語や指標は、それらの説明や比較が始まる直前にまとめて示す。
話題が唐突に切り替わって読める箇所では、つなぎの文を書き足す前に、直前の案内がそもそも要るのか、説明の並び順が適切かを見直す。
前提の説明に入れるのは、後の説明を理解するのに要る内容だけにする。
関連する知識へ話を広げない。

例をいくつも並べた後や、長い説明の後では、読者がそこまでの要点を自分で整理し、次の話題に移れるかを確かめる。
一つ一つの説明が主題とどう結びつくかを読者の推測に頼りすぎているなら、主な結果を短くまとめる。
まとめの分量は説明の長さと複雑さ、次の話題までの隔たりで決める。
総括文を残すかどうかの判定は `../SKILL.md` の「冗長の排除」にある。

- 削る例：「設定画面から変更できるので、ファイルを編集しなくてよい。つまり、ファイルを開かずに変更できる。」後半は前半の言い直しである。
- 残す例：「設定ファイルの変更は再起動するまで読み込まれないが、設定画面での変更はすぐに反映される。動いているサーバーを止められない人も、設定を変えられる。」後半は違いが誰の役に立つかを足している。
- 既出の内容を整理する例：三つの障害の事例を並べた後で「どの事例でも、通知が担当者に届くまでに 1 時間以上かかっていた」とまとめ、通知の仕組みの話へ進む。どれも各事例で一度述べた事実だが、一文に集めると、事例どうしを比べた結果と、次に扱う通知の仕組みとのつながりが追いやすくなる。

まとめで結果を振り返る文、所感や助言を述べる文は、一文ずつ次の点を確かめる。

- 直前の説明からどうつながっているか。読者のどんな判断に使えるか。
- すでに出た情報を載せ直しているなら、元の位置での役割と、まとめでの役割がどう違うか。
- 文書全体に関わる情報でも、その位置で前後とのつながりが弱くないか。弱ければ、順序を変える、省く、元の説明に組み込む、のいずれかにする。

主な結果を載せ直すときでも、節ごとに同じ分量で紹介し直す必要はない。
まとめの役割を短い結論で果たせるなら、まとめを独立した節にしなくてよい。

読み通すより、必要なときに探して使う情報（索引、作業手順、トラブルの診断など）は、用途ごとに分けて箇条書きか表にする。
確かめる項目は実際にそれを使う場所に集めておき、要る箇所からはそこを参照する。

## 取り上げる理由と既存の方法

方法・概念・製品・見方のどれであれ、新しいものを紹介する文書では、なぜそれを取り上げるのかを導入で述べる。
読者が成し遂げたいことや下したい判断をまず挙げ、紹介するものがそこにどう役立つかを書く。
調査や解説の文書なら、まだ答えの出ていない疑問や、わかりにくい点から書き始めてよい。

紹介の動機が既存の方法との比較にあるなら、両者の共通点と相違点、それでも残る課題を示す。
冒頭で取り上げる違いは主題に関わるものに限る。
比較の条件・根拠・例外を詳しく書くのは、後の節か補足にする。

課題を挙げたら、紹介するものの特徴を課題ごとに対応づけて書く。
例えば「毎月同じ集計表を手で作り直す」が課題なら、保存しておくものと、それを再び使える条件を書く。
どの手作業が要らなくなるかまで書けば、機能の差によって作業がどう変わるのかが読者に伝わる。

既存の方法の問題点を挙げるときは、どんな用途、どんな条件でその問題が起きるのかを添える。
比べる相手の長所と、適用できる範囲は書き残す。
提案が要ることを示したいからといって、相手の欠点を大きく書かない。

## 説明の順序と分量

どの順に、どれだけ説明するかは、読者が何のために読むのかと、理解するのに要る詳しさで決める。
読者がつまずきやすい関係は、例を挙げるか途中の段階を見せて説明する。
読者がすでに知っている内容は短く済ませる。
役割も重要度も異なる説明を、同じ文数、同じ運びに揃えなくてよい。
比較や手順はこの逆で、対応する項目を揃え、探したい情報が見つけやすい形を保つ。

段落ごとに、読み終えたとき読者の理解が何によって一歩進むのか（主張か、理由か、具体例か）を確かめる。
すでに出た説明を同じ役割のまま言い換えているだけの段落は、ほかの段落と一つにするか削る。
難しい説明を例に置き換えて捉え直させる段落や、離れた箇所の説明どうしを結びつける段落も、役割を持つ段落として扱う。

紹介の文では、紹介する対象や用途が出てくるまでの部分で、説明が重複していないかを確かめる。
重複していたら、意味を変えずに整理するか、一部を次の文に分ける。
例えば「チーム内でも、議事録の書き方をまとめたテンプレートを、会議の記録を残すために使っているので紹介する。」という文では、書き方をまとめたことと、記録を残すことが同じ役割を担っている。
この場合は「チームでも議事録にこのテンプレートを使っているので、紹介する。」とまとめる。
使った経験を紹介の理由に結びつける流れは、まとめた後も残す。

いくつかの対象を並べて紹介するときは、対象ごとに、どの観点を扱い、説明がどんな役割を担い、どこまで詳しいかを見比べる。
説明の量が対象によって違うなら、その差が、対象を理解したり比べたりするのに要るものかを確かめる。
一部の対象だけが別の話題や細かい条件にまで入り込んでいたら、紹介の範囲を決め直し、はみ出した説明を、その話題を扱う節か補足へ移す。

列挙では比べる軸、用語、条件を項目のあいだで揃える。
項目の数は書く内容から決める。
「理由を三つ挙げる」「長所と短所を二つずつ並べる」のように数を先に決め、その数に合わせるために、既出の説明の繰り返しや根拠の弱い項目を足さない。

一つの列挙を何文かに、あるいは何段落かに分けるときは、意味のまとまりと、項目どうしの対応の見やすさを基準にする。
文の長さに合わせて割った後は、同じ役割の項目が別の分類に属するように読めないか、項目の対応を追いにくくしていないかを確かめる。
同じ対応関係を示す箇所どうしで、述語だけを言い換えたせいで要らない違いが生まれていないかも確かめる。
長い列挙は一文にまとめた案と、箇条書きにした案を並べて比べる。

## 案内文と行動を述べる文

「見る」「読む」「確認する」「検討する」で結ぶ案内の文は、外しても読者が説明を追えるなら省く。
こうした文が、対象と行為を名指すだけで終わっていないかを確かめる。
誰がする作業なのかが曖昧に見えても、すぐに主語を補わない。
先に、その作業をそもそも書く必要があるかを判断する。
図表や文章から何が読み取れるか、どこに目を向ければ理解できるかを言えるなら、案内の代わりにその中身を書く。
行為者を書き足しても情報が何も増えない案内文は、削る方向で考える。
導入や節の終わりを締めくくる目的だけで、作業を予告する文や、読者に確認を求める文を足さない。

行動を述べる文では、書き手がしたことの報告や今後の予定なのか、読者に向けた手順や助言なのか、方法の一般的な説明なのかを書き分ける。
読者への助言が、書き手が自分でする予定のように読めてしまわないかを確かめる。
書き分けるには、主語や場面を補うだけでは足りない。
述語の形まで含めて、その文の役割が伝わるようにする。
説明から読者への提案や手順に切り替わる箇所では、読者がそれをどの場面のどの段階で実行するのかがわかり、前後の話題と無理なくつながっているかを確かめる。
操作の手順のように、文脈から文の役割が明らかなときは、主語を省いてよい。

方法が何の役に立つかを述べる文では、方法とその効果を結びつけて書く。
例えば「ログを日付順に並べ、抜けている日を確かめる」は操作を並べただけなので、「ログを日付順に並べると、抜けている日が見つけやすくなる」と書く。
一方、手順の中で次の操作を指示する「次に、ログを日付順に並べる」は、効果を書き足さずにそのまま使ってよい。
文末をまとめて書き換えず、文ごとの役割を見て決める。

どの資料を読むか、どう調べるかを読者が選ぶための案内は、読者の行動や判断に役立つなら残す。
「手がかり」も、証拠から原因を推し量る場面のように字義どおりに使うなら、言い換えずにそのまま使ってよい。

節の終わりの要約や比較は、読者が説明を追うのにそれが要る箇所を選んで置く。
定義・式・詳細を参照させるときは、参照先を節番号か見出しで示す。

ほかの箇所へ案内する文には、案内先に載っている内容を短く書く。
「〜を考えるための」「〜を広げるための」といった目的を述べる句は、参照先の中身を特定する役に立っていなければ省く。
その句が、扱う対象の範囲や、そこで加わる情報を言い表しているなら、目的の形をやめ、違いそのものを書く。
省いた後でも、案内先の中身が読者にわかる状態を保つ。

## 例の選び方と引き継ぎ

定義や手順を身につけるための文書では、入力から操作を経て結果に至るまでを追える代表例を示す。
題材ごとに、次の形の例を使う。

| 題材 | 例の形 |
|---|---|
| 数式 | 小さな数で計算してみせる例 |
| プログラム | 入力と、それに対する出力 |
| 比較 | 条件を揃えた利用場面 |

概要や規模感を伝える文書では、例を主な理由がわかるものだけに絞る。

例を出すときは、それで何を確かめるのかと、出た結果が何を意味するのかを書き添える。
その後の理由・条件・対処も同じ例で追った方がわかりやすいなら、例を替えずに使い続け、前の段階から変わった情報や操作を明示する。
新しい例に替えるときは、その例によって読者の理解にどんな違いや関係が加わるのかを確かめる。
例を統合したり削ったりするのは、その例が示している条件と結果、読者に及ぶ影響を確かめてからにする。
同じ仕組みを示す例どうしでも、理解や判断に要る違いがあるなら、その違いを示す短い説明は削らない。
途中経過を見せるのは、仕組みをつかむのに役立つところまでにする。
内容の重なる追加の例や検算は、補足へ回すか削る。

## 対象・操作・結果

示す情報は説明の目的に合わせて選ぶ。

| 説明の目的 | 書くこと |
|---|---|
| 調査 | 何を明らかにしたいのか |
| 機能 | それで何ができるのか |
| 性能の差 | 何と何を比べ、どれだけ違ったのか |

「検証した」と作業を報告して終えず、検証の結果まで書く。

対象をどう選び、集め、分類したかを書くときは、それらの対象を後で何の紹介・比較・分析に使うのかが、見出しか前後の文から読み取れるようにする。
選んだ理由だけを書き、対象と後の説明との関係は読者が補うしかない状態になっていないかを確かめる。
その関係が前後からすでに明らかなら、案内の文を書き足すより、不要な作業の報告を削る方を考える。

概念や仕組みを説明するときは、まず、それがどの場面で、何に対して、何をするものなのかを書く。
例えば中央値の求め方を教える文書なら、最初に「極端に高い家賃が混じったデータでも典型的な額をつかむため、中央値を求める」と目的を書く。
目的の次に、「全件を小さい順に並べ、真ん中の値を取る」と操作を書く。
専門語・数式・計算手順は、それが何をするのか、対象どうしがどう関係するのかを読者がつかめる位置で初めて出す。

製品名・部材・性質・数値を本文に初めて出すときは、それが文書の問いや前後の説明とどう関わるのかを確かめる。
事実を一文で短く述べれば話題のつながりも伝わる、とは見なさない。
唐突に読めるなら、説明の文を書き足す前に、関係する文と一つにできないか、置く位置を変えられないかを考える。
後の説明を理解するのに使わない情報は省く。

何かが変わる、何かが作用すると書くときは、何が、どんな条件のもとで、どんな操作によって、どうなるのかを示す。
変わるのが手順なのか、それとも計算に使う値や出力なのかを書き分ける。
変化の大きさや形が文章だけでは伝わらないなら、数値・型・実例を添える。
比喩で述べる場合でも、実際にどういう関係なのかを書く。
